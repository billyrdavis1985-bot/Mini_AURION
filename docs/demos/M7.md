## 2. Kill mid-run from the Monitor page

A second serial leg started under
`--task-id m7kill4`; at ~15 s in, the operator
pressed kill on the Monitor's Live page for
`m7kill4-serial`. The runner terminal stopped
mid-leg (no summary line — the process died).
`proc.json` afterwards:

```json
{"status": "killed", "end_status": "killed",
 "killed_at": "2026-11-22T00:01:56Z",
 "refund": {"count": 1,
            "released_nano": 17486750}}
```

One in-flight model-call reservation refunded
($0.0175). The chain ends `... tool_call,
settle, kill` — the kill receipt is the last
line, filed by agent `monitor`.

Two earlier kill attempts on already-finished
legs were correctly refused:

```
refused: "task 'm7kill2-serial' is not running
  (ended)"
```

That refusal is the pid-reuse guard, phase 1
(`kill_task` in `mini_aurion/monitor.py`): the
receipts already show `task_end`, so the pid in
`proc.json` may belong to an unrelated process
by now, and killing it would be killing a
stranger. Phase 2 (start-time comparison) stays
a backlog row.

## 4. Dead-man's switch: silence pages, beats pass

The monitor writes `{ts, pid}` to
`eval/monitor-heartbeat.json` on every served
request; `--check` exits nonzero unless the
beat is fresh (`check_heartbeat`,
`HEARTBEAT_INTERVAL_SECONDS = 60`).

Silence (monitor stopped), exit 1:

```
python -m mini_aurion.monitor --root eval
  --check
monitor silent: heartbeat is 11330s old
  (interval 60s) under eval
echo $LASTEXITCODE
1
```

Alive (page open and refreshing), exit 0:

```
python -m mini_aurion.monitor --root eval
  --check
monitor alive: heartbeat 1s ago (pid 13072)
echo $LASTEXITCODE
0
```

Demo-environment note: the beats initially
never landed because a fossil monitor (pid
55072, started Nov 14, before heartbeats
existed) was still squatting on port 8787, and
Windows let the new monitor bind the same port
— both showed LISTENING, and the browser kept
hitting the fossil, which serves pages but
never beats. Killing the fossil fixed it. The
transcript keeps this because it is the honest
failure mode: a second listener silently eats
the traffic. Documented limit stands: a dead
machine cannot page; full coverage wants the
check running elsewhere.

The beat-age math reads UTC as UTC
(`calendar.timegm`, PR #105 — `mktime` had
read the `Z` stamps as local time, pushing
every age hours negative):

```python
def receipt_age_seconds(row: dict | None
                        ) -> float | None:
    if not row or not row.get("ts"):
        return None
    try:
        stamp = time.strptime(row["ts"],
                              "%Y-%m-%dT%H:%M:%SZ")
    except ValueError:
        return None
    # timegm, not mktime: the stamp is UTC
    # (note the Z), and mktime reads it as
    # local time ...
    return time.time() - calendar.timegm(stamp)
```

## 5. STALE: unit-tested, not tripped live

STALE renders as a
`<span class="stale">STALE</span>` flag beside
the task name on the Live page when a live
pid's last receipt is older than
`STALE_SECONDS` (300). The code path is real
and unit-tested
(`test_live_page_flags_a_silent_live_task_as_stale`,
with a `STALE_SECONDS = 10**12` negative
control that fails as it must), but the live
chain never tripped it: kill to resume took
minutes, not 5 silent minutes on a still-live
pid. The task doc asked for a STALE flag
caught before the resume; this transcript
records the miss instead of staging one.

## 6. Confinement: stated, not staged

No live WRITE tool exists to abuse the store,
so there is no live refusal to show. The gate
is in `ToolWrapper.call`
(`mini_aurion/tools.py`): any WRITE-class call
whose target resolves inside the registered
state dir is denied with a receipt before the
backend runs:

```python
if action_class == "WRITE" \
        and self._state_dir is not None \
        and isinstance(args.get("path"), str):
    target = os.path.normcase(
        os.path.abspath(args["path"]))
    if target == self._state_dir \
            or target.startswith(
                self._state_dir + os.sep):
        ...
        raise ToolDenied("STORE_PROTECTED",
                         f"{name}: {reason}")
```

`None` (no state dir registered) means the
gate is off — documented, tested
(`tests/test_confinement.py`, 8 tests green).
The remaining `[kernel]` limit stands: on the
operator's single-user platform there is no
second UID, so OS-level separation waits on a
broker service.
